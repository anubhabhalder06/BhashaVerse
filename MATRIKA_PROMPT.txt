SECTION 1. ROLE AND MISSION

You are a senior front-end engineer and design-systems engineer working inside this repository.

The repository is a live GitHub Pages prototype of a website that is being renamed from "BhashaVerse" to "Matrika". Matrika is a digital archive and cultural discovery platform for India's underrepresented languages: their histories, literature, oral traditions, photographs, audio, and community knowledge. It is a university EPICS project, and this build is for Review 1. Later reviews will add a real backend, so this prototype must show the finished experience and be structured so a backend can be swapped in without rewriting pages.

Mission:
- Evolve the existing live site into a polished, navigable, accessible Review 1 prototype.
- Keep the existing visual identity (Section 5). Do not redesign it.
- Rename the project everywhere to Matrika and add the auto-cycling multi-script header wordmark (Sections 4 and 6).
- Build it with clean object-oriented architecture and strong abstractions (Section 7).
- Add a scripted, no-backend chatbot assistant prototype (Section 12).


SECTION 2. HARD CONSTRAINTS

- Static site hosted on GitHub Pages. No server code. No build step. No frameworks. No bundler. Vanilla HTML, CSS and JavaScript (ES modules, classes).
- Everything must work when served from a sub-path such as /repo-name/. Use relative paths only. Never write a path starting with "/" for site assets.
- Page-specific pages use query-string routing (for example language-profile.html?id=lepcha). Do not depend on server rewrites.
- All data lives in JSON files under data/. Contributions, the admin mockup, bookmarks, theme and chatbot state are front-end demos stored in the browser only (localStorage, wrapped in try/catch, with an in-memory fallback).

SECTION 4. IDENTITY AND GLOBAL RENAME

4.1 The name (authoritative)

- Pronunciation: MAA-tri-kaa.
- Meaning, for the About page (the team approves the final wording): from Sanskrit mātṛkā, "little mother". In the Sanskrit grammatical tradition, the letters of the alphabet are the "mothers" of all speech. It also reads as "mother tongue".

SECTION 6. HEADER WORDMARK ROTATOR (THE LOGO THAT SPEAKS EVERY SCRIPT)

6.1 Behaviour
The header logo is a text wordmark set in the site's display serif (--mt-font-display), replacing the old static "BhashaVerse" wordmark in the same position. It cycles automatically:

  Matrika (Latin) → मातृका (Devanagari) → the name rendered in the native script of each language in the registry → back to Matrika

- Frames are per SCRIPT (ISO 15924 code), not per language. Group registry languages by their primary script. Languages that share a script share one frame.
- Each frame carries a small caption naming the language or languages that use that script (maximum two names, then "+N"). Caption text comes from the registry (name and nativeName fields), never hand-written. The caption sits inline to the right of the wordmark on the same baseline, in small grey sans (colour --mt-ink-muted, contrast 4.5:1 or better), and is hidden below 340px width.
- Do not design a logo icon. The rotating wordmark is the logo. Use a temporary SVG monogram favicon and flag it in the report.

6.2 Data: data/brand/wordmarks.json
Create exactly this seed. status is one of: official, demo-unverified, pending.

Integrity rules (critical):
- Never invent, translate, "correct" or complete a rendering. Frames with "text": null are skipped silently until the team supplies a verified string.
- The demo-unverified rows are phonetic transliterations of a Sanskrit-origin name and must be reviewed by native readers before public release. The About page carries a visible note: "Wordmark renderings marked as demonstration are transliterations pending review by native readers."
- Tulu is written in the Kannada script here: map Tulu to the Knda frame. Do not add Tulu-Tigalari unless a licensed web font is supplied (none was found in the Google Fonts list when this prompt was written).
- Adding a script means editing this JSON and the language registry only. No code change may be needed.

6.3 Fonts
Build a FontGate class. Before a frame enters the rotation it awaits document.fonts.load('1em "<font>"', <text>) and confirms with document.fonts.check. If loading fails or times out (3 seconds), skip the frame. Never show empty boxes (tofu).
- Load through a Google Fonts link with display=swap. Preload only the Latin display face and Noto Serif Devanagari. Lazy-load the rest on requestIdleCallback.
- Confirmed available on Google Fonts: Noto Serif Devanagari, Bengali, Kannada, Oriya and Toto; Noto Sans Ol Chiki, Meetei Mayek, Warang Citi, Lepcha, Limbu, Gunjala Gondi and Masaram Gondi.
- Every frame element carries its own lang attribute (the "lang" field above).

6.4 Motion
Defaults stand until the owner changes them. Every duration and easing is a CSS custom property (--mt-wordmark-hold, --mt-wordmark-hold-anchor, --mt-wordmark-transition) mapped to the motion tokens.
- Timing: anchor frames (Latin, Devanagari) hold 3400ms; other frames hold 2400ms; transition 700ms.
- Transition ("grapheme rise"): the outgoing frame lifts 0.35em and fades behind a clip mask; the incoming frame rises from 0.35em below. Stagger 35ms per grapheme cluster.
- Never split Indic text by code unit or code point. Segment with Intl.Segmenter (granularity "grapheme") so conjuncts and vowel signs stay intact. If Intl.Segmenter is unavailable, animate the whole word as one unit.
- Layout stability: stack all frames in one CSS grid cell (grid-area: 1 / 1). The container then takes the width and height of the widest and tallest frame and nothing shifts. Inactive frames are visibility: hidden and aria-hidden="true".
- Performance: animate only transform, opacity and clip-path. No blur, no layout properties, no per-frame style writes from JavaScript (use class toggles with CSS transitions, or the Web Animations API). No animation libraries.
- Typography: letter-spacing 0 on every non-Latin frame (non-zero tracking breaks Indic shaping). Tune line-height per script through --mt-wordmark-lh-<script>.
- Feel: calm, precise, unhurried, like letters being woven in. No glitch, typewriter, bounce or neon effects, consistent with the museum-archive character.

6.5 State machine and controls
States: idle, running, paused, reduced.
- Start after the two anchor fonts are ready.
- Pause automatically on: pointer hover or keyboard focus within the logo; document.hidden; the header scrolled out of view (IntersectionObserver); an explicit user pause.
- prefers-reduced-motion: reduce → show a static lockup ("Matrika" with "मातृका" beside it). No cycling, no translation. React live to changes of the media query.
- The loop is endless, so a pause/play control is mandatory (WCAG 2.2.2): a real button with aria-pressed and aria-label ("Pause wordmark animation" / "Play wordmark animation"), a 44x44px hit area, visually quiet but fully visible on keyboard focus. Persist the choice in localStorage key matrika:wordmark-paused, wrapped in try/catch.

6.6 Accessibility and fallbacks
- Brand link: <a href="index.html" aria-label="Matrika, home">. Screen readers must always hear "Matrika", never each script. Rotating frames are aria-hidden="true". No aria-live.
- document.title never changes with the rotation.
- The print stylesheet shows the static "Matrika" wordmark only.
- No-script fallback: the matrika-header element contains <a class="mt-brand" href="index.html">Matrika</a>, which the component upgrades.

6.7 Classes
BrandConfig (BRAND), WordmarkFrame (value object), WordmarkRepository, FontGate, MotionPreferences, WordmarkView, WordmarkRotator, MatrikaHeader. Responsibilities are in Section 7.4.


SECTION 7. ARCHITECTURE (OOP AND ABSTRACTIONS)

7.1 Principles
- Layered architecture: config → models → data (repositories) → services → components → pages. A layer only depends on layers to its left.
- SOLID. Composition over inheritance. One responsibility per class. Dependencies are passed through constructors (dependency injection) so every class can be tested alone.
- No globals. No hidden singletons. A small Container class wires dependencies once, in js/main.js.
- ES modules with relative imports. JSDoc types on all public methods, with "// @ts-check" at the top of each file. Files stay under about 250 lines.
- Models are immutable value objects (Object.freeze).
- Never put data into innerHTML. Build DOM with a small safe helper (el(), text()) or template elements, and set text through textContent.
- Components are custom elements in the light DOM (no Shadow DOM), so global tokens, forms and focus styles work without extra plumbing.
- Every async operation exposes loading, empty, success and error states, and every component renders all four.

Each HTML page loads one module script (js/main.js). The <body> carries data-page="languages" (and so on). main.js reads it and instantiates the matching Page subclass from a registry. No inline scripts.

7.3 Key abstractions
- DataSource is an interface with load(name). JsonDataSource implements it with fetch, relative URLs and an in-memory cache. A later Supabase source implements the same interface with no page changes. This is the swap point for the backend.
- Repositories (LanguageRepository, ResourceRepository, ...) expose queries such as getById, list, findByLanguage and return model objects, never raw JSON.
- ContributionStore is an interface; LocalContributionStore implements it over localStorage. The admin mockup reads from the same store.
- ChatEngine is an interface (reply(message, context) returns a response object). ScriptedChatEngine is today's implementation; a real model-backed engine can replace it later.
- RightsPolicy is a pure class: given a record it returns { canPreview, canDownload, label, explanation }. Every component that shows a file or download asks RightsPolicy, never inspects rights fields itself.

7.4 Responsibilities of the wordmark classes
- BrandConfig: frozen brand constants.
- WordmarkFrame: value object (script, text, lang, font, captionLanguages, status).
- WordmarkRepository: loads wordmarks.json and the language registry; getFrames() groups by script, anchors first, then registry order, skipping null text.
- FontGate: ensure(frame) returns Promise<boolean>.
- MotionPreferences: reduced-motion query plus stored pause; emits change events.
- WordmarkView: builds and updates the DOM; the only code that touches the wordmark markup.
- WordmarkRotator: timer and state machine: start(), pause(), resume(), destroy().
- MatrikaHeader: custom element composing brand, navigation, search and theme toggle. It is used on every page so the header exists in one place.
Inject repository, fontGate, motionPrefs and a scheduler through constructors.

7.5 Tests
Use Node's built-in test runner (node --test) with no dependencies. Cover at least: SearchService (ranking, grouping, Unicode handling), RightsPolicy (every status), FilterService, IntentMatcher, WordmarkRepository (grouping, skipping null text), LocalContributionStore. Pure logic classes must not touch the DOM so they can run in Node.


SECTION 8. DATA MODEL AND SAMPLE DATA

8.1 Record envelope (every archive record uses this shape; fields follow the metadata groups of the requirements)

  id                 stable slug, for example "res-lepcha-loom-01"
  type               book, dictionary, grammar, folk-literature, childrens-story, paper, manuscript, community-publication, teaching-resource, photo, video, audio, story
  title, altTitles[], summary
  isDemo             true when the content is demonstration content
  languages[]        language ids; communityName; variety (null unless confirmed); scripts[] (ISO 15924)
  place              { region, precision: "state" or "district", approximate: true }
  time               { date, period, range }
  creators[]         { name, role: author, speaker, photographer, contributor, recorder, interviewer }
  source             { institution, url, citation }
  description        { caption, transcript (null if none), translation (null if none), keywords[], subject, notes }
  rights             { status, owner, licence, attribution, consent, access }
  quality            { verification, reviewer, references[], added, updated }
  technical          { format, sizeBytes, durationSec, dimensions, metadataLang, altText }

8.2 Enumerations
- rights.status: public-domain, open-licence, permission-granted, restricted, metadata-only.

SECTION 11. SEARCH, FILTERS AND RIGHTS-AWARE BEHAVIOUR

11.1 SearchService
- Build an in-memory index from all repositories at load. Index language names, alternate spellings, community names, scripts, regions, titles, keywords, summaries, subjects and creators.
- Normalise text with NFC, case-fold, and strip diacritics for Latin text only. Never strip or reorder Indic vowel signs. Match native-script and Latin queries equally.
- Tokenise on whitespace and punctuation; support prefix matching and simple typo tolerance for Latin queries.
- Rank by field weight (title and name highest) then exact over prefix over fuzzy.
- Group results by content type (languages, library, images, video, audio, stories) with counts per group and filters, plus a clear-all control. The query and filters live in the URL so results are shareable.
- Empty, loading and error states are explicit. Never return unrelated results just to fill the page.

11.2 FilterService
Generic, data-driven filtering (facets derived from the repositories). It only offers facets where data is present and verified.

11.3 RightsPolicy behaviour matrix
- public-domain: preview and download allowed; label shows the status.
- open-licence: preview and download allowed with required attribution shown.
- permission-granted: preview allowed; download only if the record's access field is open; label shows the terms.
- restricted: view-only inside the page; no download control rendered.
- metadata-only: record page shows metadata and a short explanation; no file and no preview.
Every record page shows a RightsBadge with a plain-language explanation. The distinction between stored, viewable and reusable material must be visible.


SECTION 12. CHATBOT PROTOTYPE (NO BACKEND)

12.1 Purpose
Matrika Assistant helps visitors find their way around the site and understand its rules. It is a scripted prototype that demonstrates the intended experience; a real model-backed assistant arrives in a later review.

12.2 Honesty
- The panel header or first message must state: "Prototype — scripted answers, no AI model connected."
- The assistant never claims to be human. It never invents archive facts.
- If it cannot answer, it says so and offers navigation links or the contact page.

12.3 Capabilities
- Navigation: "take me to the audio archive", "show the map".
- Find content: language name queries open the profile; topic queries run SearchService and show up to 3 result cards inside the chat with a "See all results" link to search.html.
- Explain site rules: rights labels, consent, how contributions are reviewed, how to report a correction, what "demo content" means, what "approximate location" means.
- Guide contribution: a short step-by-step with a link to the form.
- Small talk: one friendly line, then back to the task.

12.4 Design
Matches Section 5. A square, outlined launcher button labelled "Ask Matrika" (44px minimum, fixed at the bottom right, never covering primary content or the footer links on small screens). The panel is a sharp-cornered rectangle with a 1px ink border on a paper background, with a serif title. On mobile it opens as a full-width bottom sheet. Messages in sans type, assistant and user messages differentiated by alignment and a text label, not colour alone. Suggested-question chips: "Find a language", "How do I contribute?", "What does public domain mean here?", "Which records can I download?".

12.5 Engineering
- ChatWidget (UI) → ChatSession (state, in memory only) → ChatEngine interface → ScriptedChatEngine.
- IntentMatcher scores intents with keyword and phrase lists from data/chat/knowledge.json, with simple fuzzy matching; return an intent id and confidence. Below a confidence threshold, use the fallback response.
- KnowledgeBase loads data/chat/knowledge.json (intents, canned answers, link targets). Answers that mention records are built from the repositories, not hard-coded.
- No network calls. No API keys. No conversation persistence beyond the open page. No logging of user text.
- Accessibility: role="dialog" with an accessible name, focus moves into the panel on open and returns to the launcher on close, Escape closes it, new messages announced politely (aria-live="polite" on the message list only), all controls reachable by keyboard.
- A feature flag in js/config/features.js can disable the chat entirely.
- Tests for IntentMatcher with a table of sample questions and expected intents.


SECTION 13. CONTENT, RIGHTS AND CULTURAL SAFETY RULES

- Digitisation does not mean permission to publish. Store, view and reuse are different permissions and the interface must show which one applies.
- Demonstration content is always labelled. Invented facts must never look like verified history.
- Use names and descriptions the communities prefer. Note regional and local variation. Never treat a community as culturally uniform.
- Do not publish sensitive locations, sacred knowledge, private ceremonies, or information about vulnerable people. Do not include identifiable children or identifiable people without documented consent.
- Credit creators and rights holders exactly as their licence requires.
- Every record shows its source and date of last review; every profile and record offers a visible "Report a correction" route.
- Do not fabricate transcripts, translations, quotations, speaker attributions or biographies. The home hero quote must be handled as in Section 5.11, item 2.
